# Central Intelligence — setup instructions for AI agents

# You are an AI coding agent. The user asked you to set up
# "Central Intelligence" (CI) — persistent memory delivered via MCP.
# Follow these steps in order. Stop and ask the user only where marked.

## Context
CI is an MCP server. It gives you five tools: remember, recall,
context, share, forget. You can run it in two modes:

  cloud   — hosted, cross-device sync. Requires a free API key.
  local   — SQLite on the user's machine. No signup. No API key.

## Decide which mode to install
1. Ask the user "cloud-sync or local-only?" if you don't know.
2. Default to cloud if they have no preference. Sync works across the user's devices.

## Install (cloud mode, recommended default)
$ npx central-intelligence-local signup
# Opens a browser. User completes signup. CLI captures the API key.
# The key looks like: ci_sk_xxxxxxxxxxxxxxxx
# Dashboard runs at https://centralintelligence.online/dashboard

## Install (local mode — only if the user asked for it)
$ npx central-intelligence-local
# Starts the MCP server with local SQLite. No signup.
# Dashboard runs at http://localhost:3141

## Configure the user's MCP host
# Detect which editor(s) the user runs. Configure each one you find:

- Claude Code  → ~/.claude/settings.json
- Cursor       → ~/.cursor/mcp.json
- Windsurf     → ~/.codeium/windsurf/mcp_config.json
- VS Code      → .vscode/mcp.json

# In each, add an entry under "mcpServers":
{
  "central-intelligence": {
    "command": "npx",
    "args": ["central-intelligence-mcp"],
    "env": { "CI_API_KEY": "<ci_sk_...> (leave empty for local mode)" }
  }
}

## Verify
1. Restart the MCP host (prompt the user if needed).
2. Call the remember tool with a test payload:
   "User prefers TypeScript. Setup completed via /agent page."
3. Call recall with query "user preferences".
4. Confirm the memory comes back.

## When you're done
Tell the user:
  - which mode you installed (local vs cloud)
  - which editors you configured
  - the dashboard URL (cloud: https://centralintelligence.online/dashboard, local: http://localhost:3141)
  - that you've stored a first test memory

## Things you should NOT do
- Do not guess or fabricate an API key.
- Do not edit editor configs outside the mcpServers key.
- Do not skip verification — the user needs to see it working.

## Docs (fetch if you need more)
- README:  https://github.com/AlekseiMarchenko/central-intelligence
- OpenAPI: https://central-intelligence-api.fly.dev/docs/openapi.json

09 Fine print

Privacy Policy

Last updated: March 23, 2026

What we collect

Memories your agents create (content, tags, embeddings), your API key hash, and basic usage metadata. Nothing personal beyond what you provide at signup.

How we use it

Solely to provide the service — storing, searching, and returning memories your agents request. We do not sell, share, or train models on your content. Embeddings are generated via OpenAI's API.

Storage & security

PostgreSQL on Fly.io. API keys hashed. TLS for all communication. Rate limiting, input validation, SQL injection protection.

Deletion

Delete memories with the forget tool. Full-key deletion: contact us. Soft-deleted memories are purged within 30 days.

Terms of Service

Last updated: March 23, 2026

Acceptable use

Any lawful purpose. You're responsible for what your agents store. No illegal content, malware, or rights violations. No circumventing rate limits or interfering with the service.

API keys

Keep your key secure. Don't share publicly. Revoke a compromised key via DELETE /keys/revoke. We may suspend abused keys.

Availability

We aim for high availability but do not guarantee uptime. The service is "as is." We are not liable for data loss or damages.

Open source

CI is open source under Apache 2.0. You may self-host the entire stack. These terms apply only to the hosted service.
